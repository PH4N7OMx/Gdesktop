# Публикация в GitBook

Название документации: **GummyGram-documentation**.

## Импорт архива

1. Войди в GitBook и создай пространство документации с названием `GummyGram-documentation`.
2. Открой функцию импорта содержимого. Названия элементов интерфейса могут отличаться в разных версиях GitBook.
3. Загрузи `GummyGram-documentation.zip`: в нём Markdown-страницы и `SUMMARY.md` с оглавлением.
4. Проверь порядок страниц, блоки TypeScript/JSON и внутренние ссылки.
5. Прикрепи `GummyGram-plugin-sdk.zip` к странице «Первый плагин» или размести SDK в публичном репозитории и добавь ссылку на него.
6. Опубликуй сайт документации и проверь его в браузере без авторизации.

GitBook поддерживает импорт нескольких Markdown-страниц из ZIP. Подробности: [официальная инструкция импорта](https://gitbook.com/docs/getting-started/import).

Имя пространства и публичный адрес на `gitbook.io` — разные настройки. Доступность адреса и возможности оформления зависят от аккаунта и текущего тарифа; архив не создаёт и не бронирует адрес.

## Обновления через Git

Для регулярных обновлений можно подключить Git Sync к репозиторию с этими Markdown-файлами. Корень документации — `docs/GummyGram-documentation`, начальная страница — `README.md`, оглавление — `SUMMARY.md`.

В отдельном репозитории документации достаточно разместить содержимое этой папки в корне. `.gitbook.yaml` из папки подходит для такого размещения. При синхронизации всего репозитория клиента укажи соответствующий корень документации в конфигурации GitBook.

Не загружай в GitBook `tdata`, сессии userbot, `.env`, журналы с личной перепиской, зависимости `node_modules` и локальные настройки аккаунтов.
