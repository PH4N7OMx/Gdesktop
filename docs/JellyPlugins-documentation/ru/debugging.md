# Отладка и частые ошибки

Начни с карточки плагина: проверь статус, открой «Журнал действий», затем повтори один конкретный шаг. Поддерживается `jelly.log()`; браузерная консоль, Node.js debugger и точки останова TypeScript в клиенте не предоставляются.

| Что происходит | Что проверить |
|---|---|
| Пакет не устанавливается | Это JSON-файл `.jelly` из упаковщика; размер до 1 МиБ, `apiVersion: 1`, правильный манифест |
| Установился, но ничего не делает | Установка не запускает код. Включи плагин и подтверди права |
| Кнопка не появилась | В манифесте заявлено `ui: true`, право подтверждено, активация дошла до `ui.addAction` |
| После сохранения настроек не работает | Сохранение останавливает процесс. Включи снова |
| `PERMISSION_DENIED` | Право заявлено в манифесте и подтверждено; ID чата / домен точно совпадает |
| `CHAT_UNAVAILABLE` | Чат известен текущему аккаунту; открой его в клиенте |
| `BUTTON_UNAVAILABLE` / `ATTACHMENT_UNAVAILABLE` | Сообщение загружено, тип поддерживается, для вложения разрешены источник и получатель |
| `RATE_LIMIT` / `FLOOD_WAIT` | Выдержи `retryAfter`. Чтение истории тоже расходует лимит Telegram |
| Новые сообщения не приходят | Нужен `readChats`. Событие касается входящих сообщений; для старых используй `getHistory` |
| При быстрых событиях теряются значения | Асинхронные обработчики пересекаются. Используй флаг `busy` или очередь |
| После изменения TypeScript код прежний | Снова проверь типы, упакуй, установи новый `.jelly` и выдай права |
| Запуск заблокирован ОС | Исполнение требует Windows AppContainer. Ошибка указана в карточке; другие платформы пока не запускают плагины |

## Логировать ошибку API

Этот фрагмент используется внутри функции активации или обработчика; `chatId` и `text` — параметры твоего сценария.

```typescript
try {
  await jelly.telegram.sendMessage(chatId, text);
} catch (cause) {
  const error = cause as PluginError;
  jelly.log(JSON.stringify({ code: error.code, retryAfter: error.retryAfter }));
}
```

Тип импортируется через `import type { PluginError } from "../sdk-types";` для проекта внутри `examples/`. Не записывай пароли и полный текст переписки в журнал.

## Проверить изменение

1. Выполни `npm run check` в SDK.
2. Упакуй `node scripts/pack.mjs examples/my-plugin`.
3. Установи новый пакет с тем же ID: он заменит прежний и потребует подтверждения прав.
4. Проверь один сценарий и его журнал. Начни с кнопки или предпросмотра перед отправкой сообщений.

«Посмотреть код» показывает установленный JavaScript, а не исходный TypeScript. Это помогает убедиться, что установлен нужный пакет. Если сервер уже получил запрос, остановка плагина не гарантирует его отмену; проверь результат перед повтором.
