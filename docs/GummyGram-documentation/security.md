# Разрешения и безопасность

## Граница доверия

Плагин считается недоверенным кодом. Его манифест, описание, название и любые запросы к API не являются подтверждением безопасности.

Клиент исполняет JavaScript через QJSEngine в отдельном процессе Windows AppContainer без сетевых capabilities. На процесс установлен Job Object: один процесс, лимит памяти и завершение при закрытии управляющего объекта. Внутри движка нет Node.js, DOM, Python, произвольных Qt-объектов или API системных команд.

Единственный объект связи с клиентом передаёт JSON-запросы. Основной процесс проверяет метод, параметры, действующие разрешения, состояние аккаунта и лимиты. Проверка выполняется заново для каждой операции.

Системные источники: [AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation), [QJSEngine](https://doc.qt.io/qt-6/qjsengine.html).

## Права пользователя

- Чтение и отправка разрешаются отдельно для каждого заявленного чата.
- Сетевой доступ разрешается отдельно для каждого точного HTTPS-домена.
- Хранилище, расписание и кнопки имеют собственные разрешения.
- Разрешения можно сузить при включении, сняв ненужные пункты.
- Выключение отзывает разрешения и прекращает выполнение.
- Выход из аккаунта останавливает плагины и отзывает разрешения этого аккаунта.
- Обновление пакета требует нового подтверждения; разрешение связано с хешем всего пакета.

Чтение новых сообщений или истории вместе с внешним HTTP позволяет передавать содержимое переписки на разрешённый сайт. Клиент показывает предупреждение об этом сочетании. Ограничение файлов устройства само по себе не защищает от такой передачи.

## Что не выдаётся плагину

`tdata`, сессионные ключи, пароль 2FA, коды входа, аккаунты браузера, доступ к внутренним объектам клиента, запуск программ, DLL и команд оболочки. Нет общего права «изменять устройство».

Плагин не может запросить неизвестное разрешение: пакет будет отклонён. Любая внешняя библиотека должна быть упакована в JavaScript и использует ту же изоляцию, что и основной код.

## Файлы runtime

Для запуска AppContainer клиент копирует собственный исполняемый файл и DLL из своей папки в отдельную папку `GummyGram/plugin-runtime` внутри локальных данных Windows. Доступ AppContainer выдаётся только на чтение и исполнение этой копии. Доступ к исходной папке клиента или `tdata` не расширяется.

Это может потребовать дополнительного места на диске, особенно для статической сборки. Директории разных версий runtime автоматически не очищаются в API 1.

## Ограничения модели

Изоляция не гарантирует отсутствие всех уязвимостей. Возможны ошибки движка, ОС и посредника API. Нужны актуальные зависимости, проверка реализации и испытания в собранном клиенте.

В API 1 нет каталога проверенных плагинов, цифровых подписей автора или антивирусного анализа. Указанное имя автора не подтверждено. Проверки SDK и хеш пакета не заменяют аудит безопасности.

Пользователь может вручную изменить локальные файлы своего аккаунта; защита не рассчитана на противодействие владельцу устройства или уже работающему под его правами вредоносному ПО.

Вступление в каналы, кнопки ботов, копирование вложений, редактирование, реакции и история имеют отдельные разрешения по чатам. Копирование вложений может передавать их содержимое и подписи получателю.
