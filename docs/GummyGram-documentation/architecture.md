# Архитектура и проверка клиента

## Компоненты

| Компонент | Ответственность |
|---|---|
| `plugin_package` | Валидация формата, разрешений, версии API и хеша пакета |
| `plugin_manager` | Экземпляры по аккаунтам, состояние, разрешения, API, события и лимиты |
| `plugin_sandbox` | AppContainer, Job Object, подготовка копии runtime и запуск процесса |
| `plugin_worker` | Изолированный QJSEngine, JSON-протокол и ограничение времени исполнения |
| `gummygram-plugins/sdk/runtime.js` | Интерфейс JavaScript, Promise-запросы и подписки; также встроен в ресурсы клиента |
| `settings_plugins` | Установка, подтверждение доступа, настройки, кнопки и журнал |
| `gummygram-plugins` | Типы TypeScript, упаковщик, примеры и тесты SDK |

Worker запускается специальным аргументом до инициализации основного клиента. Он проверяет, что действительно находится в AppContainer. Пакет и настройки поступают через канал связи; файлы аккаунта worker не открывает.

Основной процесс не доверяет worker: проверяет размер и частоту кадров, порядок ID запросов, метод, параметры и разрешения. После остановки поколение экземпляра меняется, чтобы поздние ответы не попадали в новый запуск.

## Сборочная зависимость

Клиенту требуется Qt Qml для QJSEngine. В подготовку Qt добавлен `qtdeclarative`; Windows-линковка использует `userenv` и `advapi32`. Если готовый кеш Qt не содержит Qml, зависимость нужно подготовить заново. Для пакетных сборок нужен соответствующий пакет разработки Qt Qml.

Для Windows требуется поддержка AppContainer и атрибута Job List при создании процесса. Неподдерживаемая ОС должна приводить к отказу запуска, без менее защищённого режима.

## Проверить перед выпуском

1. Собрать клиент на целевой платформе и проверить старт без установленных плагинов.
2. Установить `jelly.hello`, подтвердить права, нажать кнопку и проверить сохранение счётчика после перезапуска.
3. Проверить реальный токен worker: AppContainer, отсутствие сетевых capabilities, лимит памяти и запрет дочерних процессов.
4. Попытаться запустить worker напрямую: он должен завершиться без чтения пакета.
5. Проверить запрет незаявленных чатов, сайтов, неизвестных методов и подделанных JSON-запросов.
6. Проверить приватные IP, DNS rebinding, редиректы, ошибки сертификатов и чрезмерный HTTP-ответ.
7. Проверить бесконечный цикл, переполнение памяти и потоки событий: клиент должен продолжать работать, плагин — остановиться.
8. Проверить доставку и ID сообщений, ответы, оплату Stars, FloodWait, отзыв прав во время запроса и неопределённый результат при остановке.
9. Проверить два аккаунта, обновление пакета и сохранение лимитов.
10. Проверить повторный запуск клиента и отсутствие автоматического запуска после ошибки.

Эти проверки — критерии выпуска, а не утверждение, что они уже выполнены. Полная сборка и испытания приложения в ходе подготовки данной реализации не выполнялись.
