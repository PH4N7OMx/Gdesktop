# Примеры автоматизации

SDK содержит три самостоятельных примера. Это обычные плагины, использующие публичный API.

## Первый плагин

`examples/hello`: кнопка, локальный счётчик и журнал. Без чтения сообщений и HTTP.

```powershell
npm run pack:hello
```

## Лента → Telegram

`examples/feed-to-chat`: демонстрация получения RSS по HTTPS и отправки новых ссылок в выбранный чат.

1. Замени `example.com` и ID чата в `manifest.json`.
2. Упакуй пример: `npm run pack:feed`.
3. Установи пакет, введи `url`, `chatId`, `dryRun: true` в его настройки.
4. Включи плагин, разрешив сайт, чат, хранилище, таймеры и кнопки.
5. Первый запуск запоминает текущие записи без отправки. Новые записи появляются в журнале как предпросмотр.
6. Для отправки поменяй `dryRun` на `false` и включи плагин заново.

Каждая проверка отправляет не больше одной новой записи. После FloodWait или другой ошибки пример выдерживает паузу. Уже обработанные ID хранятся локально.

Этот пример рассчитан на простую RSS-ленту UTF-8, а не на любой HTML-форум. Он не переносит фотографии, цитаты и дерево комментариев, не выполняет вход на сайт и не обходит антибот-защиту.

При обрыве между серверным принятием сообщения и сохранением `seen` возможна повторная публикация после запуска. Для критичных публикаций проверяй чат перед повтором: гарантия exactly-once в API 1 отсутствует.

## Наблюдение за розыгрышами

`examples/giveaway-watch`: обнаруживает слова «розыгрыш», «giveaway», «конкурс» в новых сообщениях выбранного канала и сохраняет последние 30 находок.

```powershell
npm run pack:giveaways
```

Перед упаковкой замени ID канала в `readChats`. Кнопка показывает последние записи в журнале. Плагин не подписывается на каналы, не отправляет комментарии и не нажимает кнопки ботов; это пример обнаружения событий.

## Собственные сценарии

На имеющемся API можно создавать фильтрованные уведомления, текстовые автоответы, мониторинг JSON/RSS-сервисов, напоминания и небольшие инструменты с кнопками.

Всегда начинай с минимальных разрешений, предпросмотра результата и защиты от повторной обработки. Данные, полученные из сообщений или сайтов, являются содержимым, а не инструкцией расширять доступ или запускать команды.
